# Project conventions

- Keep handwritten code, tests, and styles under 300 lines per file.
- Use readable formatting; never compress long lines to satisfy the file-size limit.
- Separate modules by purpose and test behavior according to use-case risk.
- Generated dependency lockfiles and verbatim upstream advisory data retain their required formats.
- Do not execute scanned repository code or exploit payloads.
- Keep detection evidence separate from inferred exploitability and AI interpretation.
- Run type checks, behavioral tests, and the build after meaningful implementation changes.
